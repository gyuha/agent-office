# Agent Office v9 — 단일 방 모듈 규격

[실행](index.html) · [기계 판독 규격](layout.json)

v8 office-c의 따뜻한 목재·식물·작은 직원 분위기를 바탕으로 새로 직접 그린 오리지널 픽셀 자산입니다. 이번 v9에서는 이미지 생성 도구를 사용하지 않았으므로 생성 프롬프트는 없습니다. office-c에서 색상 통계만 추출했으며 그림 픽셀을 자산에 복사하지 않았습니다. 기존 게임이나 외부 자산은 사용하지 않았습니다.

## 격자·팔레트

- 논리 타일 16×16px, 화면 렌더 배율 **항상 2배**. 모든 모듈 크기는 16의 배수입니다. 1 논리 픽셀은 2×2 CSS 픽셀입니다. HUD용 비트맵 글꼴도 같은 격자입니다.
- scene 좌표는 바닥 기준 x는 오른쪽, y는 아래쪽(관객 방향)입니다. 3/4 평행 시점으로 윗면과 앞면을 함께 그립니다.
- 모든 PNG는 투명 또는 아래 고정 24색만 포함합니다. 알파는 0/255입니다. 이미지 생성 후처리 대신 처음부터 논리 해상도에서 그리고 마지막에 같은 팔레트로 정합합니다. CSS image-rendering: pixelated, Canvas imageSmoothingEnabled=false를 사용합니다.
- 원본 팔레트는 office-c의 median-cut 24색에서 빈도가 낮아 빠지는 녹색·블루·자두색 3색을 원본의 실제 픽셀 샘플로 보강한 뒤 layout.json에 고정했습니다. 기능색은 그 팔레트에서 가장 가까운 색에 매핑합니다. 따라서 블루/자두도 원본의 차분한 팔레트 범위입니다.

## 방과 모듈 조립

별도 관리자실·벽·칸막이가 없는 **한 사무실**입니다. orchestrator는 뒷벽 중앙의 큰 책상에서 팀원 방향을 보고 앉습니다. 휴식 가구는 왼쪽 가장자리에 두며 통로를 막지 않습니다.

- room_floor는 16×16 반복. room_back_window는 64×96 수평 반복. room_side는 양 끝에서 16×16 수직 반복. room_front는 바닥 앞쪽에서 수평 반복합니다. 모서리는 측벽이 뒷벽 위에 그려져 접합됩니다. 방 크기는 모두 16배수이므로 부분 타일이 생기지 않습니다.
- pod_chair + actor slot + pod_desk는 **동일 월드 기준점**을 공유합니다. 보통 책상은 96×80, 관리자 책상은 128×96입니다. 캐릭터 슬롯은 pod 기준점과 같으며 스프라이트 발 기준점 [24,60]을 맞춥니다.
- provider 표시는 모니터 위쪽 23×3 스트립과 명패 왼쪽 3px 스트립, 이름/provider 텍스트입니다. claude=green, codex=blue, gemini=plum. 상표 모양은 없습니다.
- 이름표는 pod+[0,15], 상태는 그 아래 13px입니다. 관리자는 pod+[0,22]에 ORCHESTRATOR를 표시합니다. 흰 머리·안경·골드 의상과 더 큰 책상도 관리자를 구별합니다.
- HUD PNG는 16px 폭으로 반복하며 라이브 문자는 font_ascii PNG로 찍습니다. 상단은 날짜·시간·활동 수, 하단은 완료 작업·토큰·테스트입니다. 좁은 화면에서는 하단 문구가 압축됩니다. 모두 목업 수치입니다.

## 그리기 순서

1. 바닥 → 뒷벽 반복 → 측벽 → 앞쪽 마감.
2. 소품과 pod, 이동 인물을 월드 발 y로 안정 정렬합니다.
3. pod 내부는 의자 → 불꽃 → 캐릭터 → 책상·모니터 → 타이핑 손 오버레이 → 휴대폰 오버레이 → provider 마크·명패입니다. 책상에 가려지는 타이핑 손은 actor_hands로 보강합니다.
4. 성과 숫자·말풍선·Zzz는 월드 좌표 오버레이로 마지막에 그립니다.
5. HUD는 월드 Canvas 밖에 고정하고 방의 스크롤에 따라 움직이지 않습니다.

## 스프라이트와 이름 규칙

- `actor_v0.png`~`actor_v3.png`: 헤어·의상 조합 4개. `actor_v4.png`: 관리자. 외형은 같은 시트의 모든 프레임에서 동일합니다.
- 각 시트 192×448, **프레임 48×64**, 4열×7행, 발 기준점 **[24,60]**.
- 행 0 working: 4프레임, 8fps. 행 1 down / 2 up / 3 left / 4 right: 각각 4프레임, 8fps. 행 5 sleeping: 2프레임, 1fps. 행 6 phone: 2프레임, 3fps. sleeping/phone의 나머지 두 칸은 반복 예비 칸입니다.
- `actor_hands.png`: 48×16 프레임 4개, [24,16], 월드 위치는 pod+[0,-14]. 본체 working 프레임과 같은 8fps로 타이핑합니다.
- `fx_flame.png`: 64×64×4프레임, 기준 [32,60], 7fps; 불꽃 색 2단과 입자. `fx_points.png`: 32×32×4프레임, [16,20], +3/+10을 선택하고 위치·알파를 1.5초 동안 바꿉니다.
- `fx_bubble.png`: 64×32×2프레임, [32,30], Done!/PR up!을 선택하여 약 1.4초 표시합니다. 말풍선은 이름·상태 명패와 경계가 겹치면 표시를 건너뜁니다. `fx_zzz.png`: 32×32×2프레임, [16,20], 1fps와 작은 호흡 오프셋입니다.
- `font_ascii.png`: ASCII 32~127, 셀 8×10, 직접 정의한 5×7 글리프와 6px 글자 간격. 소문자는 대문자 모양으로 매핑합니다.
- 자산 이름은 `{room|pod|lead|prop|actor|fx|hud}_{name}.png`, 외형은 `actor_v{0..4}.png`입니다. 개별 프레임을 내보낼 경우 `actor_v{n}_{working|walking_down|walking_up|walking_left|walking_right|sleeping|phone}_{00..03}.png`을 사용합니다.

## N=1~16 배치 규칙

```
columns = N <= 3 ? N : N <= 6 ? 3 : 4
rows = ceil(N / columns)
width = 224 + columns * 128
height = max(512, 224 + rows * 128)
pod(i) = [224 + (i % columns)*128, 256 + floor(i/columns)*128]
orchestrator = [width/2, 144]
```

| N | 열×행 | 월드 크기 | 화면 방 크기(2배) |
| --- | --- | --- | --- |
| 3 | 3×1 | 608×512 | 1216×1024 |
| 6 | 3×2 | 608×512 | 1216×1024 |
| 10 | 4×3 | 736×608 | 1472×1216 |
| 16 | 4×4 | 736×736 | 1472×1472 |

모듈 사이 좌우 최소 32px, 행 기준점 간격 128px, 방문 통로 y=208을 예약합니다. 왼쪽 x=32..144는 휴식 소품 전용입니다. 소파 발 [80,284], 커피 테이블 [80,356], 침대 [80,height-48], 책장 [48,96], 화이트보드 [width-80,96]입니다.

왕복 동선은 자리 → [x,y+48] → [x+64,y+48] → [x+64,208] → 방문점 순서입니다. 화이트보드 방문점은 [width-80,208], 관리자 방문점은 [width/2+88,208]이며 돌아올 때 역순입니다. 이동 경로의 길이로 보간하고, 매 프레임 현재 좌표가 목표를 따라가므로 상태를 바꾸어도 자리로 순간이동하지 않습니다. 데모는 고정 통로 기반이며 실제 scene에서 여러 보행자의 상호 충돌 회피는 추가해야 합니다.

## 상태 전환과 제어

- 상단의 3/6/10/16 버튼 또는 1~16 선택 메뉴로 즉시 재배치합니다. 에이전트별 자동/working/phone/sleeping 선택과 모두 작업·자동 데모 버튼이 있습니다.
- working은 타이핑하며 10초 이후 16초 주기로 통로를 따라 방문합니다. 왕복 3초+방문 1초+3초이며 매 16초 주기마다 (2+주기번호)%N인 한 명만 방문 슬롯을 사용합니다. 여러 방문자가 같은 통로에서 겹치지 않게 하는 단순 예약 규칙입니다. 고속 이동을 따라잡는 속도 상한은 240 논리 px/s입니다.
- 자동 0번은 0~3초 working, 3~5초 phone, 5~7초 sleeping, 7~12초 working을 반복합니다. 10초 이내 양방향 전환이 보입니다.
- 수동 phone은 12초 후 장기 idle로 판정해 sleeping으로 전환합니다. 수동 sleeping은 자리에서 엎드립니다. 침대는 배치용 소품이며 침대까지 걸어가 눕는 시퀀스는 향후 확장입니다.
- 포즈는 0.35초 크로스페이드합니다. 이동 중 idle로 바꾸면 현재 좌표에서 자리 쪽으로 돌아간 후 idle 포즈가 보입니다.
- 브라우저 폭 약 900px에서는 페이지 자체가 옆으로 넘치지 않고 **방 컨테이너만 스크롤**됩니다. 픽셀 크기를 유지하기 위해 비정수 축소를 하지 않습니다. 전체 방 preview는 full-page 캡처이므로 1000px보다 높을 수 있습니다.

## 재생성·적용

`python3 assets/mockups/v9/build_parts.py`로 PNG와 layout.json, 로컬 file://용 layout-data.js를 재생성합니다. Pillow만 필요합니다. index.html은 네트워크나 서버 없이 모든 PNG·JS를 상대경로로 로드합니다. layout-data.js는 JSON의 동일 데이터 복사이며 fetch(file://) 제한을 피하기 위한 배포 파일입니다.

실제 client/scene에서는 JSON 규격을 읽고 동일한 anchor·정렬·프레임 규칙을 적용하면 됩니다. 이 시안은 프로젝트 실행 코드나 기존 자산을 수정하지 않습니다. 실제 agent 상태·토큰·시간 연결, 방문 동시성 제어, 접근성·모션 감소 정책은 통합 단계에서 추가해야 합니다.
