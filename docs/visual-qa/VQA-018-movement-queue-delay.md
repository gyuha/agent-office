# VQA-018 이동 대기열이 직렬이라 상태와 화면이 최대 30초 넘게 어긋남

- 심각도: 높음
- 추정 담당: scene (`actors.ts` 방 단위 직렬 대기열)
- 상태: closed
- qa 회귀 테스트 필요

## 증상
레인 겹침(VQA-008)을 없애려고 방 전체 이동을 한 명씩 차례로 처리한다. 그래서 여러 명의 상태가 동시에 바뀌면 뒤 순번은 자기 차례가 올 때까지 이전 상태 자세로 남는다.
- N16 away→working: manager 0~4초, 이어서 p-0, p-1 … p-5 순서로 이동한다. 마지막 p-5는 33초에 출발해 약 39초에 자리에 도착한다. 그 동안 working인 멤버가 빈백에 기대어 쉬고 있다.
- N16 working→away도 같은 순서로, 마지막 멤버는 약 33초 동안 away인데 자기 자리에 앉아 있다.
- N6 away→working: 마지막 art#94A2는 10.25초에 출발해 약 13초에 도착한다.

흐름은 다음과 같다.
```
상태 동시 변경 → manager 이동 → 멤버0 이동 → 멤버1 이동 → … → 마지막 멤버 도착(N16: ~39s)
                    (그 동안 뒤 순번은 이전 상태 자세 유지)
```

## 재현 조건
- N=16, 480px, `setTransition('away','working', 0~60000)` 1초 간격 추적
- N=6, `setTransition('away','working', 0~12000)` 250ms 간격

## 스크린샷

## 왜 어색한가
"일하는 상태인데 빈백에서 쉬고 있음"이라는, 원래 피해야 할 장면이 수십 초 동안 이어진다. 실제 Paseo에서 상태를 보고 판단하는 사용자에게 틀린 정보를 준다.

## 기대 모습
상태 반영은 몇 초 안에 끝난다. 겹침은 출발을 조금씩 엇갈리게 하거나(예: 0.3~0.5초 간격) 레인 안에서 간격을 유지하는 방식으로 풀고, 전체 직렬화는 피한다. 기준 예시: N16 전원 전환이 5초 이내에 시작된다.

## 재확인 결과 (2026-11-07, 2차 재확인)

- solo, N3, N6, N10, N16에서 양방향 `setTransition`을 100ms 간격으로 0~9초 측정했다.
  - 출발: 모든 액터가 300ms 안에 걷기 시작했다.
  - 도착 완료: solo 2.8초, N3 6.6초, N6 4.7초, N10과 N16 5.3초
  - 이전 상태 자세로 머문 최대 시간: 400ms(기준 1초 이내)
  - 순간이동: 100ms당 최대 이동 22 logical px로 연속 보행이었고, 위치가 튀는 프레임이 없었다.
  - 레인 겹침: 걷는 두 인물 사이 거리가 60 logical px 미만인 경우 0건
  - 캡처에서도 같은 레인의 인물이 앞뒤 간격을 유지한다.
- N3이 6.6초로 가장 긴데, 인원이 적어서 빈백까지 가는 경로가 길기 때문이다. 시작은 300ms 안이라 기준을 만족한다.
